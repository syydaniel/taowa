# 阶段 2：调研和实测（自动）

目标：弄清楚这个 skill 到底能干什么、怎么装、用起来什么样，并且**真的跑一遍**，留下能放进画面的证据。产出都放 `research/`。

## 做什么

1. **拿到原件。** 把仓库放到 `research/repo/`（`git clone --depth 1`）。这是别人的代码：只读，不执行里面的安装脚本；要装就按它 README 的官方方式装，装之前先看一眼它会往哪里写东西。
2. **读。** SKILL.md、README、它的脚本。写 `research/它是什么.md`：一句话说清它解决什么问题；触发方式；三个最能说明问题的用法；它自己声称的效果。
3. **真跑。** 设计一个观众一看就懂的小任务，开和不开各跑一遍（或者跑它的典型用法），把过程录下来：
   - 命令行的东西用 `T term <名字> -- "命令一" "命令二"`，真实输出会存成 `app/src/term/<名字>.json`，画面里用 `<Term>` 回放。
   - 要展示某个文件（比如它的 SKILL.md）用 `T term <名字> --file 路径 --from 1 --to 60`，画面里用 `<FileView>` 圈画。
   - 网页或者界面用 `rec/record.js`（Playwright，按 `rec/scenarios.js` 里写的步骤操作并录屏；第一次用要在 `rec/` 里 `npm install`）。
   - 结果是图片或文件的，存进 `app/public/shots/`。
4. **记数字。** 实测得到的每个数字写进 `research/事实清单.md`，每条标【已核】【部分核实】【未核实】和出处（哪条命令、哪个文件、哪个网页）。未核实的不进旁白。
5. **找翻车。** 实测时哪里不好用、哪类任务不适合、装的时候卡在哪，也记下来。视频里讲代价比只讲好处更可信。
6. **看对标。** 对标视频的结构（钩子怎么起、演示放在第几秒、怎么引导评论）记三五条就够，不照抄文案。

## 讲的是作者自己的 skill 时

原件就在本机，第 1 步改成读它的目录；"真跑"就是用它真的做一次它该做的事，过程里的日志和产物就是证据。

## 交出去的东西

- `research/它是什么.md`、`research/事实清单.md`
- `app/src/term/*.json`（真实输出）、`app/public/shots/*`（截图和产物）
- `运行记录.md` 里记一笔：实测花了多久、卡在哪

这些随文案一起给作者看，不单独停。
